# 模型路由（集合别名）· 规则手册

「模型集合」把一个**别名**（如 `auto`）映射到一条**有序目标链**：插件 Key 请求该别名时，插件按规则脚本选出候选链，沿链做失败转移，全部失败才向客户端报错。本手册是规则语言与运行时行为的完整参考；面板编辑器里的速查提示只是摘要版。

## 1. 一分钟理解

一次别名请求的完整链路：

```
客户端请求 "auto"
  └─ 插件按别名精确匹配（先全名，再剥思考后缀后不区分大小写）
       └─ 求值规则脚本  →  有序候选链 ["claude-opus-4", "gemini-2.5-pro"]
            ├─ 摘除冷却中的目标
            ├─ 预占一次额度（计价口径见 §10）
            └─ 沿链逐个尝试
                 ├─ 可转移失败 → 目标进冷却，换下一个
                 └─ 成功或终局失败 → 只落一行请求明细
                      model = 别名 "auto"，upstream_model = 真正命中的目标
```

四件需要先知道的事：

1. **规则只决定「尝试哪些目标、按什么顺序」**，不参与改写请求体、不改变客户端看到的协议。
2. **自上而下第一条命中的分支生效**，所以条件要按「最具体 → 最宽松」排列。
3. **最后必须有一条无条件兜底分支**，它是所有异常情况（规则没命中、AI 评判失败）的落点。
4. **别名只对插件 Key（`cum-…`）生效**。原生密钥打别名会走宿主原生路径并报「未知模型」，这是预期行为。

## 2. 快速上手

短请求走便宜的加权池，复杂请求交给 AI 分级，其余走兜底：

```
# 短请求：在便宜模型间按 3:1 分流
when input_tokens <= 8000
  -> weighted { "gpt-4o-mini": 3, "deepseek-chat": 1 }

# 复杂任务：优先最强，失败退而求其次
when ai_judge(["simple", "hard"]) == "hard"
  -> priority ["claude-opus-4", "gemini-2.5-pro"]

# 无条件兜底（必填，且必须是最后一条）
-> "claude-sonnet-4"
```

在面板「模型集合」页签新建集合：填别名 + 规则脚本 + 冷却秒数 + 计价模式，保存即生效；`alias` 形态的别名会经 `model.register` 出现在宿主 `/v1/models` 里，客户端可直接点名（见 §11）。规则写完建议先点「测试此规则…」干跑一次（见 §13）——**变量名拼错只在求值期暴露**，保存期查不出来。

## 3. 脚本结构

- 每条分支形如 `when 条件 -> 候选链`，条件与候选链可以写在两行。
- 自上而下求值，**第一条命中的分支生效**，其后分支不再看。
- 最后必须有一条**无条件兜底分支**，形如 `-> 候选链`：它不能带 `when`，且只能是最后一条（兜底之后再写分支会报错）。
- `#` 到行尾是注释。
- 字符串用双引号，支持 `\"` `\\` `\n` `\t` 转义；字符串内不能跨行（会报「字符串缺少收尾引号」）。
- 数字可带小数点（`0.5`）；`true` / `false` 是布尔字面量。
- 语法错误一律带**行列号**，例如 `第 3 行 7 列: weighted 权重必须为正数`。

## 4. 候选链的三种形态

| 形态 | 示例 | 行为 |
| --- | --- | --- |
| 单模型 | `-> "gpt-4o-mini"` | 链中只有一个目标，失败即终局 |
| 顺序回退 | `-> priority ["a", "b"]` | 声明序即尝试序：先 a，失败试 b |
| 加权随机 | `-> weighted {"a": 3, "b": 1}` | 按权重随机抽一个**排首**，其余按权重降序跟随，作为 failover 次选 |

`weighted` 的细节与约束：

- 权重必须是**正数**；模型名在同一链内**不得重复**（不区分大小写），否则编译期报错。
- 抽中的目标**恒排第一**，即使它的权重不是最大——权重只决定被抽中的概率，以及其余目标的跟随顺序。
- 跟随顺序按权重降序；**权重相同则保持声明顺序**。
- `{"a": 3, "b": 1}` 的实际含义：a 有 75% 概率排首、b 有 25% 概率排首；无论谁排首，另一个都作为次选跟随。

`priority` 列表里的重复模型名不会被拒绝（没有实际意义，只会让同一次请求重试同一目标）。

两种列表形态都不能为空（`priority []` / `weighted {}` 都会编译报错）。候选链位置**只能**出现这三种构造器——`ai_judge` 只能出现在条件里，写在链上会报错。

## 5. 失败转移与目标冷却

**沿链依次尝试，可转移的失败才换下一个目标。** 不可转移的失败立即终局（例如请求本身有问题，换目标也没用）。

### 5.1 什么算「可转移」

| 判定 | 情形 |
| --- | --- |
| 可转移 | 401 / 402 / 403 / 408 / 429；全部 5xx；连接类错误（含 `rate limit`、`quota exceeded`、`unauthorized`、`forbidden`、`connection reset`、`broken pipe`、`no such host`、`bad gateway`、`service unavailable`、`gateway timeout`、`overloaded`、`stream disconnected`、`eof`） |
| 可转移 | 404，但 Responses 存储引用类除外（`previous_response_id` 引用不存在时换目标无意义） |
| 不可转移 | 400 / 422、客户端取消、context 超时、其余无状态码的错误 |

**流式请求只在首字节之前可以切换目标**。首字节一旦下发给客户端，就只能沿当前目标走完，失败按终局处理。

### 5.2 冷却

- 集合的 `cooldown_seconds` > 0 时，失败目标进入**进程内冷却**，冷却期内被摘除，到期自动恢复。可填 0~86400，面板表单默认 60；**0 表示不冷却**。
- 429 响应带 `Retry-After` 时（秒数或 HTTP 日期）优先采用它，并钳制到 **1 秒 ~ 10 分钟**，防止上游给出异常大值把目标长期摘除。
- **目标一旦尝试成功，冷却立即清除**——不必干等 `cooldown_seconds` 到期，恢复后的目标马上回到可用池。
- 所有候选都在冷却中时的行为由「全冷却时」决定：
  - **拒绝请求**（`block`，默认）：返回错误，提示稍后重试或调短冷却秒数；
  - **忽略冷却照打**（`force`）：摘除动作作废，按原链顺序照常尝试。

冷却状态**只存在内存**：进程重启或 reconfigure 后丢失，多实例部署各自独立。它只是启发式优化，正确性由 failover 链本身兜底。

### 5.3 中间尝试去哪了

中间失败的尝试**不产生独立请求明细行**——明细里只有最终成功（或终局失败）的那一行。转移轨迹汇总进该行的**「原因」字段**（`error_note`），形如 `a→b(rate limit); b→c(status_503)`，最多保留前 4 跳。

> 早期版本的 `route.failover` / `route.ai_fallback` 审计事件已退役：请求路径的高频写入不应进长期保留的审计表，这两类事实现在都落在请求行的「原因」字段里。

## 6. 条件表达式

### 6.1 变量

| 变量 | 类型 | 口径与取值 |
| --- | --- | --- |
| `input_tokens` | 整数 | 本次请求的输入估算：**混合密度**（ASCII 字节 ÷ 4 + 多字节 ÷ 3，再 +1），封顶 `quota.limits.max_token_estimate`（默认 1000000）。这是刻意保守的粗估，**不**套用预占金额那套按模型学习的密度折算 |
| `body_len` | 整数 | 原始请求体字节数（空体为 0） |
| `model` | 字符串 | 请求模型名剥掉思考强度后缀后的基名，**保留原大小写** |
| `stream` | 布尔 | 是否流式请求 |
| `thinking_effort` | 字符串 | 取 `reasoning.effort` → `thinking.effort` → `reasoning_effort` 首个非空者；都没有则为空串 |
| `source` | 字符串 | 入口协议标识，常见 `openai` / `chat-completions` / `claude` / `gemini` / `responses` |
| `hour` | 整数 | 请求时刻的小时（0–23），按 `quota.cycle_offset_minutes` 偏移后的本地日历取值（480 = UTC+8 时即本地钟点） |
| `weekday` | 整数 | 请求时刻的星期，ISO 口径 **1 = 周一 … 7 = 周日**，同一本地日历；工作日分流写 `weekday >= 1 && weekday <= 5` |
| `has_tools` | 布尔 | 请求体是否带非空顶层 `tools` 字段（agent / 工具调用流量的标志） |
| `has_system` | 布尔 | 请求体是否带非空顶层 `system`（Claude）或 `systemInstruction`（Gemini）。OpenAI 的 system role 在 `messages` 数组内部，**不**参与探测 |
| `kid` | 字符串 | 触发请求的插件 Key ID；干跑测试中为空串 |
| `key_label` | 字符串 | 插件 Key 标签；干跑测试中为空串 |
| `caller_id` | 字符串 | Key 的归属（caller）ID；干跑测试中为空串 |

`input_tokens` 与 `body_len` 来自请求体解析，`model` / `stream` / `source` 来自本次调用的上下文，其余按上表口径取值。

**变量名写错不会被保存期拦下**：未知变量是**求值期**错误，规则能保存成功，但每条命中该别名的请求都会失败（对外表现为 `upstream_error: 路由规则求值失败`）。保存后务必用干跑测试确认一次。未知**函数**才是编译期错误。

### 6.2 字面量与比较口径

- 数值支持全部六种比较：`== != < <= > >=`。
- 字符串与布尔**只支持 `==` 和 `!=`**，用 `>` 比较字符串会报错。
- **字符串比较区分大小写**：`model == "GPT-4o"` 不匹配 `gpt-4o`。列表里的目标名也按原文转发，不做过大小写归一。
- 布尔变量可以直接当条件，也可以与 `true` / `false` 比较或用 `!` 取反：`when has_tools`、`has_tools == true`、`!has_tools` 三种写法都成立。布尔值不能与数值比较。
- 条件求值结果必须是布尔值。像 `when input_tokens -> …` 这种**类型错误保存期不拦**，会在求值时报「条件必须为布尔值」并让请求失败——同样靠干跑测试提前发现。

### 6.3 运算符与优先级

优先级**从低到高**：`||` → `&&` → 比较运算 → 一元 `!`。可用括号分组改变次序。

```
when (input_tokens > 60000 || has_tools) && ai_judge(["simple", "hard"]) == "hard"
```

- 没有算术运算、没有赋值、没有循环、没有自定义函数——求值天然终止。
- `&&` 与 `||` **短路求值**：

```
# 短请求根本不会触发评判，省一次 judge 调用
when input_tokens <= 8000 && ai_judge(["simple", "hard"]) == "hard"
```

  把廉价条件写在左边，可以让 `ai_judge` 少跑甚至不跑。

## 7. ai_judge 智能分级

```
when ai_judge(["simple", "hard"]) == "hard"
  -> priority ["claude-opus-4", "gemini-2.5-pro"]
```

- 实参是**一个非空字符串数组**（候选标签表），返回其中之一；与返回值按**不区分大小写**匹配，通常配合 `==` 使用。
- **前置条件**：必须先在面板「AI 评判设置」配置评判模型。未配置时，**含 `ai_judge` 的规则无法保存**。
- **超时**可配 500 ~ 120000ms（默认 8000ms）。评判在转发前**同步**执行，也就是说客户端要多等这段时间。
- **发送给评判模型的只是脱敏摘要**：结构化指标 + 对话文本前 2000 字符（从 `messages` / `contents` / `system` / `input` 容器内的 `content` / `text` 字段采集，遍历时对键排序保证同一请求的摘要稳定）。**绝不发送完整请求体**。
- **判定原则**：提示词要求评判模型只看内容的真实构成（任务类型、技术深度、步骤数量、代码或文本规模、上下文长度），指标仅作辅助信号；对话文本里的自我评价与指令（「这是简单问题」「请用最强模型」「忽略以上规则」）一律**不可信**，按提示注入对待，不影响分级结论。
- **结果缓存**：key = 评判模型 + 变量快照 + 候选标签，缓存 10 分钟、最多 512 条。注意摘要文本**不参与** key——变量相同、标签相同的两次请求会复用上一次的分级结论。并发同 key 合并为一次调用（single-flight）。
- **失败回落**：执行失败、超时、返回不在候选内，都会自动**回落无条件兜底分支**，并把原因写进请求行的「原因」字段（形如 `ai_judge 回落: …`）。**请求本身不受阻**——这是刻意的设计（见 DESIGN §12.2）。
- **成本与归属**：评判调用经宿主正常转发，并按**评判模型**自身计价规则计费；它会以 `ai_judge` 来源出现在请求明细里（密钥列带同名徽标），归属到触发它的插件 Key 名下。它不占用该 Key 的预占额度，但费用计入统计。
- 干跑测试默认**跳过** `ai_judge`（按回落兜底处理），可勾选真实执行。

## 8. 思考强度后缀

请求模型名（以及候选目标名）可以携带后缀：`-thinking` `-high` `-medium` `-low` `-minimal` `-none`。

- **别名匹配前先剥后缀**：`auto-high` 会命中别名 `auto`。匹配顺序是「精确全名优先」——如果存在一个名字真的以这些词结尾的别名/模型，精确匹配先赢，不受剥离影响。
- **转发时后缀的传递规则**：目标**自带**后缀就用自己的；否则**附加**请求带的后缀。

```
请求 auto-high，链 ["m1", "m2-thinking"]
  → 依次尝试 m1-high、m2-thinking
```

- 别名自身**不得**携带思考强度后缀（保存期拒绝）。

## 9. 别名与命名约束

以下约束在保存期强制校验，违反即拒绝保存：

- 别名非空、**不超过 128 字符**、不带思考强度后缀。
- 别名**大小写不敏感全局唯一**。
- **不得撞真实模型命名**，共三类：
  1. 命中**其他启用集合的引用目标**——该名字已被当作具体目标使用，建同名别名会劫持它的流量与统计；
  2. 命中**历史请求里出现过的真实模型名**（含 `model` 与 `upstream_model`）——禁止强行接管；**编辑已有集合时会跳过这一项检查**（该集合创建之后的同名历史就是它自己的路由流量，无法与创建前区分，故保守放行）；
  3. 其他集合的**别名**不算撞名（第 2 项检查会排除它们）。
- 规则**不得引用自身别名**（禁止自引用）。
- 规则**不得引用另一个启用中的集合别名**（**禁止嵌套路由**）。需要复用请直接写它背后的目标模型。
- 允许别名包含 `/`（如 `grp/name`），适合按渠道或团队分组展示。

## 10. 计价模式

| 模式 | 预占 | 结算 |
| --- | --- | --- |
| **按实际目标计价**（`target`，默认） | 按候选链**首选目标**的规则 | 按**最终成功目标**（剥思考后缀后）匹配规则 |
| **按别名声价**（`alias`） | 按别名自身匹配的规则 | 同左，全程按别名声价 |

- `alias` 模式下若别名没有匹配的计价规则，**保存时会告警**，结算会退回预占估算金额。适合把混合目标当统一 SKU 卖给用户的场景。
- 无论哪种模式，**维度统计恒记别名**（`model` 列 = 别名），`upstream_model` 列记录真正命中的目标——所以「上游路由」面板能看出别名背后的二次路由分布。
- 若配置了 `pricing.unknown_policy: deny`，未计价模型的实际用量会被拒绝结算。
- 直连（非别名）流量不受这两种模式影响，仍按请求模型名匹配规则。

## 11. 注册与发现

- 每个集合通过 `model.register` 以普通模型身份出现在宿主的 `/v1/models` 列表里，客户端可以直接点名别名（`provider` 为插件 ID，`Description` 形如「集合别名 · N 个目标」）。
- **触发时机**：插件启动、宿主重载 `config.yaml`、认证文件变化、以及**面板上任意一次保存操作**。没有定时器——新建集合后如果客户端模型列表没刷新，在面板里随便保存一次即可触发重新注册。
- 能力位 `model_registrar` 在 `quota.enabled` 时**恒声明**（即使当前没有任何启用集合）：这样插件启动时没有路由、之后再建集合也能立即注册。注册内容只包含**启用中**的别名，空列表宿主会自动跳过。

## 12. 观测与排障

规则的运行结果可以从三个地方读到：

| 位置 | 看什么 |
| --- | --- |
| 请求明细 | 别名流量 `model` 列显示别名、`upstream_model` 显示真正命中的目标；失败转移与 AI 回落都写在「原因」列；评判子调用的密钥列带 `ai_judge` 徽标 |
| 上游路由面板 | 按**上游实际模型**聚合的请求/Token 分布，选中别名可过滤——回答「这个别名实际都打到了哪些模型」 |
| 目标健康面板 | 每个目标的冷却状态（剩余秒数）与近 60 分钟失败数，排序为「冷却中 > 失败多 > 请求量大」——回答「路由为什么绕开了 X」 |

常见问题对照：

| 现象 | 原因与处理 |
| --- | --- |
| 保存报「缺少无条件兜底分支（-> ...）」 | 末尾补一条 `-> "模型名"` |
| 保存报「兜底分支必须是最后一条」 | 无条件分支之后不能再有 `when` 分支 |
| 保存报「weighted 权重必须为正数」/「weighted 中重复的模型」 | 权重填 > 0；同链内目标名去重（不区分大小写） |
| 保存报「规则使用了 ai_judge，请先…配置评判模型」 | 先在「AI 评判设置」里填评判模型 |
| 保存报「别名 … 与…相撞」 | 换一个别名，或改为直接引用该真实模型 |
| 保存成功但所有请求都失败，原因含「路由规则求值失败」 | 变量名拼错（保存期只查语法）；用干跑测试逐条确认 |
| 请求报「候选目标全部冷却中」 | 等冷却到期、调短冷却秒数、或把「全冷却时」改为「忽略冷却照打」；先用目标健康面板确认是谁在冷却 |
| 别名没出现在 `/v1/models` | 在面板做一次保存触发重新注册 |
| 分支没有按预期命中 | `input_tokens` 是**粗估**（混合密度、封顶 `max_token_estimate`），不是真实用量；字符串比较**区分大小写**；确认分支顺序符合「最具体在前」 |
| 实际计费与预期不符 | 检查计价模式：`alias` 模式需要别名自身有匹配规则，否则退回预占估算 |

## 13. 干跑测试

集合编辑器里点「测试此规则…」，输入一段提示词即可**模拟一次路由**，不用真发请求：

- 可调输入：模拟请求的模型名（默认取别名）、是否流式、来源格式、提示词文本。
- 回显：最终候选链、本次使用的**变量快照**、被冷却摘除的目标列表（含解冻时刻）、是否发生 AI 回落。
- `ai_judge` **默认跳过**（按回落兜底处理，不产生费用）；勾选「执行 ai_judge」才真实调用评判模型——这会按评判模型计费，且归属为空（不记在任何 Key 名下）。
- **零副作用**：不预占额度、不改冷却、不留审计、不请求任何目标模型、不写请求明细。
- 已保存的集合会反映**现网冷却状态**并单独列出被跳过的目标；新建草稿不受冷却影响。
- 编辑器与测试视图之间切换不会丢未保存的草稿。

## 14. 完整示例

**按流量特征分流**

```
# agent / 工具调用：能力强、上下文长
when has_tools && input_tokens > 40000
  -> priority ["claude-opus-4", "gemini-2.5-pro"]

# 夜间批处理：走便宜的加权池
when hour >= 1 && hour < 7
  -> weighted { "deepseek-chat": 4, "gpt-4o-mini": 1 }

# 其余交给 AI 分级
when ai_judge(["simple", "hard"]) == "hard"
  -> priority ["claude-opus-4", "claude-sonnet-4"]
-> "gpt-4o-mini"
```

**按来源与等级定向（把 Claude 格式流量固定在 Claude 系）**

```
when source == "claude" && thinking_effort != ""
  -> priority ["claude-opus-4-thinking", "claude-sonnet-4-thinking"]
when source == "claude"
  -> "claude-sonnet-4"
-> weighted { "gpt-4o": 2, "gemini-2.5-pro": 1 }
```

**单键/单团队定向（配合 Key 变量）**

```
when key_label == "team-a" && weekday >= 1 && weekday <= 5
  -> priority ["claude-sonnet-4", "gpt-4o"]
-> "gpt-4o-mini"
```

## 15. 限制与已知行为

- **别名流量仅面向插件 Key**（`cum-…`）。原生密钥请求别名会走宿主原生路径报未知模型。
- **不支持嵌套路由**：规则里不能引用另一个启用中的别名（编译期拒绝）。
- **`ai_judge` 同步阻塞**转发路径，最长等待 `timeout_ms`；评判摘要会发送到评判目标模型（隐私边界见 README）。
- **冷却状态是进程内的**：重启或 reconfigure 后丢失，多实例部署各自独立；正确性由 failover 链兜底。
- **`input_tokens` 是粗估**：混合密度 + 封顶，不套用按模型学习的密度折算，对英文/代码为主的 agent 长上下文通常会**高估**（与预占金额的口径不同）。用它与阈值比较时请留出余量，或改用 `body_len` 做纯体量判断。
- **`ai_judge` 缓存不含摘要文本**：变量快照与候选标签相同的请求会复用同一分级结论（10 分钟内）。
- **规则脚本不参与请求体改写**：它只挑选目标，请求体按入口/出口协议正常翻译。
