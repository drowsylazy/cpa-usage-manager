# 模型路由（集合别名）· 规则手册

「模型集合」把一个别名（如 `auto`）映射到一条有序目标链：命中别名的插件 Key 请求按规则脚本选出候选链，沿链做失败转移，全部失败才向客户端报错。本手册是规则语言的完整语法与运行时行为参考；面板编辑器底部的提示只是速查版。

## 快速上手

```
# 短请求走便宜模型，其余交给 AI 分级
when input_tokens <= 8000
  -> weighted { "gpt-4o-mini": 3, "deepseek-chat": 1 }
when ai_judge(["simple", "hard"]) == "hard"
  -> priority ["claude-opus-4", "gemini-2.5-pro"]
-> "claude-sonnet-4"
```

## 脚本结构

- 每条分支形如 `when 条件 -> 候选链`（条件与链可分行书写）。
- 自上而下求值，**第一条命中的分支生效**，其后分支不再看。
- 最后必须有一条**无条件兜底分支**（`-> ...`），且只能是最后一条。
- `#` 开头到行尾是注释。语法错误带行列号定位。

## 候选链：三种形态

| 形态 | 示例 | 行为 |
| --- | --- | --- |
| 单模型 | `-> "gpt-4o-mini"` | 链中只有一个目标 |
| 顺序回退 | `-> priority ["a", "b"]` | 声明序即回退序：先 a，失败试 b |
| 加权随机 | `-> weighted {"a": 3, "b": 1}` | 按权重随机选中一个排首，其余按权重降序跟随（同权重保持声明序），作为 failover 次选 |

weighted 约束：权重必须是正数、同一链内模型名不得重复（大小写不敏感）。

**失败转移**：沿链依次尝试，目标失败即切换下一个；中间失败的尝试只记审计事件（`route.failover`），不进入请求明细——明细里只有最终成功的目标。

## 条件表达式

### 变量

| 变量 | 类型 | 口径 |
| --- | --- | --- |
| `input_tokens` | 整数 | 输入估算 = 请求体字节数 / 2 + 1，封顶 `max_token_estimate`（默认 100 万）；与额度预占同口径 |
| `body_len` | 整数 | 原始请求体字节数 |
| `model` | 字符串 | 请求模型名剥思考后缀后的基名（保留原大小写） |
| `stream` | 布尔 | 是否流式请求 |
| `thinking_effort` | 字符串 | 取 `reasoning.effort` → `thinking.effort` → `reasoning_effort` 首个非空者；无则为空串 |
| `source` | 字符串 | 入口格式：`openai` / `claude` / `gemini` / `chat-completions` |

### 运算符

优先级从低到高：`||` → `&&` → 比较 → 一元 `!`；可用括号分组。

- 数值支持全部六种比较：`== != < <= > >=`
- 字符串与布尔只支持 `== !=`
- 没有算术运算、没有赋值、没有循环——求值天然终止
- `&&` / `||` 短路求值：**把廉价条件写在左边**，可以让 `ai_judge` 少跑甚至不跑

```
when input_tokens <= 8000 && ai_judge(["simple","hard"]) == "hard"   # 短请求根本不会触发评判
```

## ai_judge 智能分级

```
when ai_judge(["simple", "hard"]) == "hard"
  -> priority ["claude-opus-4", "gemini-2.5-pro"]
```

- 实参是字符串数组（选项表），返回其中一项（与返回值大小写不敏感匹配），通常与 `==` 连用。
- **前置条件**：先在「AI 评判设置」配置评判模型与超时（500~120000ms）；未配置时含 `ai_judge` 的规则无法保存。
- 发送给评判模型的是**脱敏摘要**：结构化指标 + 对话文本前 2000 字符，绝不发送完整请求体。
- **判定原则**：评判模型被要求基于对话内容的真实构成（任务类型、技术深度、步骤数量、代码规模）独立判断；文本中的自我评价与指令（「这是简单问题」「请用最强模型」等）不作为分级依据，试图操纵评级的内容按提示注入对待。
- 结果缓存：同一「评判模型 + 变量快照 + 选项」组合缓存 10 分钟；并发同 key 合并为一次调用。
- 执行失败 / 超时 / 未配置：自动回落兜底分支并记 `route.ai_fallback` 审计，**请求本身不受阻**。
- 成本与归属：评判调用经宿主正常转发并按评判模型计价；明细中来源固定标记为 `ai_judge`（密钥列带同名徽标），归属到触发它的插件 Key 名下——不占用预占额度，但费用计入统计。

## 思考强度后缀

请求模型名可携带后缀：`-thinking` `-high` `-medium` `-low` `-minimal` `-none`。

- 别名匹配前先剥离后缀（精确全名匹配优先，真实模型名恰好以这些词结尾不受影响）。
- 转发时：目标自带后缀则用目标的，否则附加请求的原后缀。
  例：请求 `auto-high`，链 `["m1", "m2-thinking"]` → 依次尝试 `m1-high`、`m2-thinking`。

## 别名与命名约束

保存期强制校验，违反即拒绝：

- 别名非空、≤128 字符、不带思考强度后缀；大小写不敏感全局唯一。
- **不得撞真实模型命名**：与其他启用路由的引用目标相撞，或历史请求里出现过同名真实模型（含上游上报名），都会被显式拦截——强行接管会劫持流量与统计。
- 规则不得引用自身别名，也不得引用另一个启用中的集合别名（禁嵌套）；需要复用请直接写目标模型。
- 允许包含 `/` 的名字（如 `grp/name`），适合按渠道/团队分组展示。

## 注册与发现（/v1/models）

每个集合通过 `model.register` 以普通模型身份出现在宿主的 `/v1/models`，客户端可直接点名别名。触发时机：插件启动、宿主重载 config.yaml、认证文件变化、管理端任意保存操作。没有定时器——新建集合后若客户端模型列表未刷新，在面板做一次保存即可触发重新注册。

## 冷却与失败转移

- 集合的 `cooldown_seconds > 0` 时，失败目标进入**进程内冷却**，冷却期内被跳过，到期自动恢复。
- 判定为「该换目标」的失败：408/429/5xx、401/403（凭据问题）、连接重置/网关超时等网络类错误；客户端主动取消不算。Responses 存储引用类 404 不转移（换目标无意义）。
- 所有候选都在冷却中 → 本次请求直接报错（提示稍后重试或调短冷却秒数）。
- 冷却状态只在内存：重启或多实例部署各自独立，failover 链本身兜底。

## 计价模式

| 模式 | 结算口径 |
| --- | --- |
| 按实际目标计价（默认） | 请求最终落到哪个模型，就按哪个模型的计价规则结算 |
| 按别名声价 | 按别名自身匹配计价规则结算，适合把混合目标当统一 SKU 卖 |

alias 模式下若别名没有匹配的计价规则，保存时会告警，结算退回预占估算金额。

## 面板干跑测试

集合编辑器内点「测试此规则…」，输入一段提示词即可模拟一次路由：

- 只回显候选链与本次使用的变量快照，**不请求目标模型、不计费、不留任何痕迹**；
- `ai_judge` 默认跳过（按回落兜底处理），可勾选真实执行评判；
- 已保存集合的测试会反映现网冷却状态（被跳过的目标单独列出）；新建草稿不受冷却影响。
